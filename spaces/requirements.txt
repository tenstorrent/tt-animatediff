# Space runtime.
#
# gradio is pinned exactly and MUST match sdk_version in README.md — the Hub
# builds against sdk_version, so a drift between the two means the Space runs a
# different Gradio than this file claims.
#
# README.md also pins python_version: "3.12", and that pin belongs to THIS one.
# gradio 4.44.1 pulls in pydub, which does `import audioop` — removed from the
# stdlib in Python 3.13 (PEP 594). The Hub's default image is 3.13, so the Space
# built cleanly and then died on its first `import gradio`, before app.py ran a
# single line of its own. Measured, not guessed: that is verbatim what the run
# log showed on the first deploy. Raising gradio instead would be the other fix;
# it is a larger change than this demo needs.
gradio==4.44.1
#
# The rest carry upper bounds on purpose. gradio 4.44.1 is a 2024-era pin, and
# an unbounded resolver is free to pick a future major of diffusers or
# transformers that no longer works alongside it — which would break the Space
# build with nothing in this repo having changed. These bounds are the versions
# the pipeline is actually exercised against (0.32.1 as the floor, 0.39.0 and
# 0.40.0 verified in CI and locally); raise them deliberately, after testing.
#
# `transformers<6` used to sit here, which admitted a 5.x nothing has run this
# pipeline against — the rule above, not followed. The deploy installed 5.16.1.
# Tightened to <5, the major everything here IS exercised against (4.52.4 locally),
# as a precaution rather than a measured failure: raise it after testing, which is
# exactly what the rule already said.
torch>=2.0.0
diffusers>=0.32.1,<0.41
transformers>=4.30.0,<5
accelerate>=0.20.0,<2
#
# huggingface_hub<1 is NOT belt-and-braces; it is the pin that had to be learned by
# deploying. gradio 4.44.1 declares `huggingface-hub>=0.19.3` with no upper bound, and its
# own gradio/oauth.py does `from huggingface_hub import HfFolder` -- a name removed in
# huggingface_hub 1.0. So the resolver installed 1.30.0, gradio failed to import, and the
# Space reached "Running" and then died before app.py executed a line. gradio's own
# metadata cannot protect against this, so the bound has to live here.
huggingface_hub>=0.20.0,<1
#
# pydantic<2.11 is measured, not remembered. gradio 4.44.1 pins gradio-client==1.3.0,
# whose json_schema_to_python_type() walks a schema assuming `additionalProperties` is a
# dict; pydantic 2.11 began emitting it as a bool, so gradio's own /  route raises
# `TypeError: argument of type 'bool' is not iterable` on EVERY request. The Space showed
# "Running" while serving 503s, which is the worst shape this can fail in. Bisected
# locally against the same component types app.py builds:
#     2.9.2 OK | 2.10.6 OK | 2.11.0 TypeError | 2.12.0 TypeError
pydantic>=2.0,<2.11
safetensors>=0.4.0
Pillow>=9.0.0
numpy>=1.24.0
#
# No ttnn / tt-metal: this Space is the CPU path by design — Blackhole is not
# reachable from Hugging Face infrastructure.
